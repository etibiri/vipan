## Two pre-existing bugs found and fixed during this validation pass

Neither of these was introduced this session; both were caught only
because the workflow's own test suite was actually executed rather than
assumed to pass, and both are now fixed in both the live project and the
`zenodo_release/` copy:

1. **`tests/test_reproducible_workflow.py`** — a complete test method
   (filtering-strategy discordant-accession test) had been stranded
   *after* the `if __name__ == "__main__":` guard with its `def test_`
   prefix truncated to `_discordant_accessions(...)`, which made the
   entire test module fail to import (`SyntaxError`) and silently
   prevented *any* test in the suite from running. Fixed by restoring
   the method header and moving it back above the guard, inside the
   test class; renamed to
   `test_filtering_strategy_comparison_flags_discordant_accessions` to
   describe its actual behavior.
2. **`scripts/filter_alignment_outliers.py`** — a duplicate, corrupted
   copy of the tail of `main()` (missing its leading `"r"` in
   `"reason_counts"`, i.e. `eason_counts": reason_counts,`) had been
   appended after the module's `if __name__ == "__main__":` guard,
   producing an unterminated string literal and making the script fail
   to even parse. This is the script used by the distance-filtering
   step of the pipeline. The dead, corrupted duplicate (lines 398–416)
   was removed; the real, complete, correctly-terminated function body
   earlier in the file (through line 397) was untouched.

Both fixes were verified by re-running the full test suite
(`python -m unittest tests.test_reproducible_workflow -v`): 6/6 pass,
where previously the suite failed to even collect.

## Not independently re-executed this round (documented limitation)

A full clean-checkout `snakemake ... all` end-to-end run was **not**
executed as part of this validation, for two structural reasons
identical to the ones documented earlier in this project: (1) neither
execution environment available to this session has outbound network
access to install Snakemake/conda environments, and (2) the workflow's
one deliberate manual boundary (RDP4 GUI analysis) cannot be automated
regardless of environment. What *was* verified instead: every script's
Python syntax parses cleanly (`ast.parse`, all 16 scripts in both the
live repo and the Zenodo copy); the existing unit test suite passes
6/6, including two bugs this pass discovered were not previously
covered by a passing suite; every ID-consistency and count check above
was run directly against this run's actual output files, not asserted
from memory.
